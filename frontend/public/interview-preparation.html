About the project

Quiz Master helps students practice questions based on NCERT textbooks. It prepares textbook content, builds quizzes from a reusable question bank and generated questions, grades answers, and shows learning progress.

Project parts

  • Python ingestion and Chroma content store
  • FastAPI quiz and grading backend
  • React and TypeScript student app

Project & architecture

01What problem does Quiz Master solve, and who is it for?⌄

AnswerIt helps students in classes 6–12 practice with questions grounded in their actual NCERT textbooks. The student chooses a class, subject and scope instead of relying on a generic online quiz that may not match the syllabus.

Related code
02Can you explain the full system in one minute?⌄

AnswerThere are three parts. The ingestion scripts parse and embed NCERT PDF content into Chroma. FastAPI reads that content, looks up reusable questions in PostgreSQL, generates missing questions with an LLM, grades attempts and stores progress. A React and TypeScript frontend handles selection, quiz taking, results and solutions.

03Why did you use two data stores instead of one?⌄

AnswerChroma stores textbook chunks and their metadata for content retrieval. PostgreSQL stores relational app state: questions, seen-question records, attempts, answers, profiles and performance counters. PostgreSQL also uses pgvector when assigning similarity clusters to newly generated questions.

Content & RAG

04How do you convert NCERT PDFs into usable content?⌄

AnswerThe ingestion pipeline reads the PDFs with PyMuPDF, detects headings using layout and book-specific rules, groups text into topics, extracts special content such as tables and exercises, then embeds the usable chunks with all-MiniLM-L6-v2 and stores them in Chroma.

Related codeingestion/scripts/detect_headings.py ingestion/scripts/embed_and_store.py
05What is the embedding model, and where do you use it?⌄

AnswerThe project uses the local all-MiniLM-L6-v2 sentence-transformer model. Its 384-dimensional vectors are used for textbook content storage, question similarity clustering, and comparing non-exact fill-in-the-blank text answers.

Quiz engine

06How does the backend decide which questions to put in a quiz?⌄

AnswerIt validates the requested scope and count, resolves selected chapter/topic units into allocations, then looks up unseen questions from the bank for each unit and question type. Any shortfall is generated from textbook content, and the delivered question IDs are marked as seen for that student.

Related codebackend/app/scope_resolution.py backend/app/quiz_service.py backend/app/bank_lookup.py
07How do you avoid showing the same question repeatedly?⌄

AnswerThe seen_questions table records each question delivered to each user. Bank lookup excludes those question IDs. A fresh quiz on the same topic uses this exclusion, while the explicit “requiz same questions” action replays the existing set for review.

Generation & quality

08How do you prevent generated questions from being generic or off-topic?⌄

AnswerGeneration receives a textbook chunk and a prompt for the requested question type and difficulty. The prompt asks for concept testing using that source. Generated output is parsed against a type-specific schema before it enters the question bank.

Related codebackend/app/generation.py backend/app/prompts.py
09How does the app prevent near-duplicate questions?⌄

AnswerIt hashes normalized question text to find exact duplicates and uses embeddings to assign a concept cluster when a new question is stored. Bank lookup returns at most one question from a cluster and excludes clusters already chosen for the current quiz, including across MCQ and fill-in-the-blank.

Related codebackend/app/dedup.py backend/app/bank_lookup.py backend/schema.sql
10What happens if an LLM request or its output fails?⌄

AnswerThe primary provider is retried with backoff and then a fallback provider is tried. A malformed generated question is retried during schema validation. If generation still fails, the API returns a clear error and the UI offers a retry or a smaller quiz from existing bank questions where possible.

Grading & progress

11How are the three question types graded?⌄

AnswerAn MCQ is an exact option-index match. A numeric fill-in-the-blank is compared after normalization; a text blank accepts an exact normalized answer or an embedding similarity above the current threshold. Matching earns its single mark only when every pair is right, though each row gets feedback.

Related codebackend/app/grading.py
12Why does a “requiz same questions” score not update progress?⌄

AnswerThe student has already seen the same questions and possibly their answers. Including that replay would inflate accuracy and distort weak-topic selection. The service grades it for immediate feedback but creates no attempt, answer rows or performance-counter update.

Related codebackend/app/scoring.py backend/app/routers/quiz.py

Frontend & security

13How is authentication handled?⌄

AnswerClerk handles sign-in, sign-up and sessions in React. The frontend attaches the session JWT as a Bearer token to API calls. FastAPI verifies its signature, expiry and issuer using Clerk’s JWKS, then uses the token’s subject claim as the student ID.

15How is the project configured for deployment?⌄

AnswerThe frontend has Vercel configuration and build-time VITE_ variables for Clerk and the API URL. The backend has a Render service configuration, a health endpoint, and environment variables for PostgreSQL, LLM providers and Clerk. The Chroma corpus must also be available to the backend; its build script can download an archive using CHROMA_ZIP_URL.
